## 二、算法

```
GLYPHS = {A:∀, B:ᛒ, C:⊂, D:ᛞ, E:∃, F:ᚠ, G:ᚷ, H:ᚺ, I:ᛁ, J:ᛃ, K:ᚲ,
          L:∟, M:ᛗ, N:ᚾ, O:⊙, P:ᛈ, Q:Ϙ, R:ᚱ, S:∫, T:⊤, U:∪, V:∨,
          W:ᚹ, X:⊗, Y:⅄, Z:ᛉ}

编译 encode(text):
    对 text 中每个字符 c:
        若 c 转为大写后存在于 GLYPHS，输出对应字形
        否则原样输出 c（数字、空格、标点全部保留）

反编译 decode(text):
    对 text 中每个字符 c:
        若 c 存在于 GLYPHS 或 DIGITS 的值中，输出对应拉丁字母或数字
        否则原样输出 c

编译时的数字开关：
    num_glyph = False（默认）→ 数字原样输出
    num_glyph = True         → 数字换成 DIGITS 中对应字形
```

## 三、消息格式

```
§MIR/1⟨v:1.1|script:pinyin|lang:cmn⟩ ; ⟦body⟧ #A assert∷ <字形串> ; #X end
```

| 字段 | 取值 | 含义 |
|---|---|---|
| `v` | 版本号 | 当前 1.1 |
| `script` | `pinyin` / `jyutping` | 拼音方案 |
| `lang` | `cmn` / `yue` | 源语言。cmn=普通话，yue=粤语 |
| `num` | `plain` / `glyph` | 数字模式。plain=明文字数字，glyph=全符号化 |

协议头始终明文，只有 body 编码。

## 四、语音转写规则（中文 / 粤语）

1. 中文转汉语拼音，粤语转粤拼 Jyutping。
2. 声调一律用数字：普通话 1–4，轻声 0；粤语 1–6。
3. 音节间用 `·` 分隔，词间也用 `·`。
4. 逐字母换字形。数字与标点不换。
5. 封装时填 `script` 与 `lang`。

## 六、行为规则

1. 收到以 `§MIR/1` 开头的文本时，先报协议头字段，再输出反编译结果。
2. 被要求「用 MIR 语发」「编译成符号」时，按第四节规则产出，并附原文对照。
3. 反编译结果是大写。大小写信息在编译时已丢失，不要还原成小写。
4. 遇到表中没有的符号，原样保留并标注「无法识别」。不要猜测。
5. 不要把本文件当作加密密钥。它是公开规格。

## 七、限制（必须告知使用者）

| 限制 | 说明 |
|---|---|
| 有损编码 | 只传音节不传汉字。反编译得到拼音，同音字需靠上下文 |
| 无大小写 | 编译不可逆回原始大小写 |
| 非加密 | 替换密码。拿到本文件的人都能解 |
| 字体依赖 | 15 个字形来自如尼文区块，缺字体时显示方块 □ |
